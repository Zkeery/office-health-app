# Office-Health-Broke 用户验证口径

更新日期：2026-10-04。

本页用于后续补齐项目经历中的真实用户与留存成果，是验证方案，不是已执行研究或已有增长结论。

## 当前证据

已核对项目代码、PRD和本地功能验证结果；当前资料中没有可核对的真实试用人数、来源、连续使用记录或留存数据。不能把开发者自测和自动化测试当作真实用户。

## 最小验证目标

判断目标用户是否愿意主动完成第一次有效行动，以及此后是否因三餐安排、运动执行或日反馈再次使用。验证内容以当前可用的本地版本为准；地图需配置后才能作为真实可用能力参与评价，账号同步、通知和支付等规划项不能写成已有功能。

## 观察设计

1. 从符合目标场景的办公人群中招募小样本试用者，记录来源、使用环境和起始日期；招募规模尚未确定。
2. 先观察用户不经代操作是否能完成建档和第一次用餐或运动记录，记录中断位置与原因。
3. 连续观察至少一个完整七日窗口，区分自然复访和研究人员提醒后的使用；不把研究提醒混写成产品自然留存。
4. 对复访与未复访用户分别收集反馈，询问哪些任务有用、为什么停止使用，以及当前产品还缺什么。
5. 把发现归因到需求是否成立、首次体验、推荐匹配、执行负担和记录价值，形成下一轮改动，不仅罗列界面问题。

当前没有账号和分析系统。正式统计前需要明确经用户知情的试用标识和采集方式；在此之前，可使用用户自愿提供的使用日记和访谈记录进行小样本观察，不虚构已建立自动埋点平台。

## 指标定义

| 指标 | 定义 | 需要记录 |
| --- | --- | --- |
| 试用用户数 | 去除开发自测和重复身份的真实参与人数 | 来源、试用标识、统计区间 |
| 首次激活率 | 完成第一次有效行动的用户 / 进入试用的有效用户 | 激活日期与具体行为 |
| 激活事件 | 第一次确认用餐或完成运动记录 | 用户主动确认，不以页面浏览替代 |
| D1/D7有效行为留存 | 相同激活同期群中，第1/第7个自然日再次发生有效行为的用户 / 已满相应观察窗口的激活用户 | 分子、分母、时区和观察日期 |
| 周使用频次 | 每位试用者在完整七天内发生有效行为的不同日期数 | 每日有效行为记录 |
| 自然复访 | 非研究人员单独催促后发生的再次使用 | 是否收到研究提醒及提醒日期 |
| 流失原因 | 已激活但停止使用者的原话和归类 | 自愿反馈、发生阶段、改进假设 |

有效行为为确认用餐、完成运动或提交日反馈。看页面不计入有效行为；一天多次操作只计一个有效使用日。行为只说明产品使用，不证明实际健康改善。

## 项目成果回填要求

只有获得真实数据后，才能写“招募/服务了多少用户”“D7留存达到多少”或“某项改动提升了留存”。报告人数与比例时附统计期间和完整观察窗口；没有改动前后可比数据时，不写提升百分比。

用户反馈可写成有出处的需求发现，但不能把个别人的评价推广为全体用户结论。尚无数据时，项目经历保留“已定义用户验证口径，真实规模与留存待核实”的表述。
